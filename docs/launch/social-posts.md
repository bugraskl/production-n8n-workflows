## Reddit / r/n8n

**Title:** I built 10 small, auditable n8n workflows for self-hosters

I wanted a workflow collection that optimized for reliability instead of raw template count, so I built ten focused workflows with safe first runs, one Config node, retries, setup guides, and no exported credentials.

They cover service health, domain/TLS monitoring, PostgreSQL backup verification, GitHub releases, CVEs, website changes, issue triage, and human-reviewed AI ticket classification.

Repo: https://github.com/bugraskl/production-n8n-workflows

I would value blunt feedback from people using n8n in production. What would you change before trusting one of these on your own instance?

## LinkedIn

I published an open-source collection of 10 production-oriented n8n workflows for self-hosters and small teams.

The goal is not template volume. Each workflow is deliberately small, keeps credentials out of exported JSON, uses bounded retries, documents its failure behavior, and has a safe first run.

The collection covers service health checks, domain and TLS monitoring, PostgreSQL backup verification, release tracking, CVE digests, issue triage, website monitoring, and human-reviewed AI ticket classification.

MIT licensed: https://github.com/bugraskl/production-n8n-workflows

Feedback from n8n operators is very welcome.
